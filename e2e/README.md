# E2E（真实浏览器）

六个脚本，都是用 headless Edge + CDP 驱动**真实页面**、对着**真实运行的服务**跑：

| 脚本 | 定位 |
|---|---|
| `full-flow.mjs` | **全量模拟用户**：注册 → 项目 → 画布 → 节点池 → 笔记本 → 退出/再登录，24 个检查点 |
| `notebook-move.mjs` | **笔记本 ⇄ 节点池搬运专项**：两个方向、两条入口，界面与接口双向核对，13 个检查点 |
| `folder-delete.mjs` | **删文件夹专项**：确认框文案、取消/确认、级联范围、手稿一起删、刷新一致性，11 个检查点 |
| `drag-sort.mjs` | **拖拽专项**：手稿/画布/节点池卡片/三处文件夹树排序（均含刷新后保持）、卡片拖入画布的影子内容，11 个检查点 |
| `legacy-upgrade.mjs` | **老库升级专项**：拿真实旧库副本启动服务，验证自动补列、数据零丢失、新功能可用，7 个检查点 |
| `legacy-folder-sort.mjs` | **老库上的文件夹排序**：旧库里两个文件夹的 sortOrder 能写能读、非数字被拒、老数据不受影响，8 个检查点 |
| `ui-smoke.mjs` | 更早的冒烟：登录、手稿、图片粘贴与持久化 |

## full-flow.mjs 覆盖什么

| 步骤 | 断言 |
|---|---|
| 未登录访问 `/` | 落到 `/login` |
| 注册新账号 | 落在 `/projects`（主页面就是项目列表） |
| 项目页顶栏 | 笔记本入口在「搜索/协作/设置/账号」那一批的最左，且与工具按钮之间有分隔线 |
| 新建项目 → 点项目卡片 | 进的是**真实画布** `/canvas/<id>`，不是 `/canvas/new` 那种空页 |
| 画布建节点 | 节点落在点击位置、且在视口内 |
| 画布富文本 | 加粗 / 标题 2 / 颜色三种格式都真的写进 `<h*>` 与 `color`，且点工具栏不会退出编辑 |
| 节点池 | 标题与「从笔记本导入」同一行；能新建文件夹 |
| 笔记本 | 新建手稿、输入、自动保存显示「已保存」、加粗生效 |
| 文件夹 | 新建「素材」→ 在其下新建「配色」→ 把手稿移进「素材」→ 删「素材」后整棵子树（含「配色」）**和里面的手稿一起删**，未归档里不会出现它 |
| 搜索 | 搜不到给空态文案，搜得到命中 |
| 双向导入 | 手稿送入节点池 → 手稿从笔记本消失；从节点池导入里能看到卡片、悬浮出预览、点一下变成手稿、卡片从池里消失（搬运语义） |
| 顶栏与弹窗 | 思维导图回 `/projects`、左上角 logo 回 `/projects`、Ctrl+K 命令面板是中文、设置/账号设置弹窗能开且 Esc 能关 |
| 退出 → 再登录 | 回到 `/projects`，刷新后项目与画布节点都还在 |

## notebook-move.mjs 覆盖什么

只盯一件事：**笔记本 ⇄ 节点池是搬运，不是复制**。界面看着对了不代表库对了，
所以每一步都拿服务端接口回对一次。

| 步骤 | 断言 |
|---|---|
| 新建一篇手稿并写正文 | 列表里出现，等自动保存落库 |
| 「送入节点池」 | 提示写「已移入节点池」；跳回 `/notebook`；列表里**没有**这篇了 |
| 服务端核对 | `GET /api/manuscripts` 不含它，`GET /api/manuscripts/:id` → 404 |
| 池子里 | 恰好多出 1 张卡片，名字来自手稿标题 |
| 刷新 | 列表与池子仍然符合搬运语义（不是只改了前端状态） |
| 「从节点池导入」 | 提示写「已转为手稿」并打开新稿；再开菜单，池子里**一张卡都不剩**；`GET /api/users/node-pool` 为空 |
| 内容 | 标题与正文一路搬回来没丢 |
| 另一条入口 | 节点池面板「从笔记本导入」：卡片进池、手稿同时从笔记本消失，接口同样 404 |
| 回到笔记本 | 列表只剩还原出来的那一篇，第二篇没留残影 |

## folder-delete.mjs 覆盖什么

种子数据（接口建好，跑完即弃的新账号）：`空箱`（空）、`父级 → 子级 → 孙级`（孙级里有 1 篇手稿）、
`单层`（1 篇手稿）、`旁系`（对照，不该被动到）、`打开着`（1 篇手稿，稍后开着它删父目录）。

| 步骤 | 断言 |
|---|---|
| 空文件夹 | 弹框写「这个文件夹是空的」，取消后原样保留 |
| 有子孙与手稿 | 弹框写「2 个子文件夹、1 篇手稿会一起删除」，取消后树一点没变 |
| 确认删除 | 父/子/孙全消失、手稿跟着删（未归档为 0、列表里也没有）；旁系与兄弟文件夹还在；选中项从「孙级」回落到「全部手稿」 |
| 旁系手稿 | 同批里没被删的那篇还在，能打开、正文完整 |
| 单层文件夹 | 删后里面手稿一起没了；弹框只提手稿、不提子文件夹 |
| 刷新 | 界面上的文件夹集合与服务端 `GET /api/manuscript-folders` 完全一致；被删手稿不会"复活" |
| 删完建同名 | 「父级」能重新创建，且是 depth=0 的叶子，旧子级/孙级不会回来 |
| 开着删 | 正在编辑的手稿所在文件夹被删：退回 `/notebook`、提示「手稿已随文件夹删除」、手稿在服务端也查不到了 |
| 节点池空文件夹 | 右键 → 删除也会弹确认（以前没有卡片就直接删），文案「这个文件夹是空的」，取消后还在 |
| 节点池有子文件夹+卡片 | 文案「1 个子文件夹、1 个节点卡片会一起删除」，不再说"退回未归档" |
| 节点池确认删除 | 父子文件夹与卡片一起消失，界面上也看不到残留卡片 |

## drag-sort.mjs 覆盖什么

种子：项目 1 个 + 画布 3 张（甲/乙/丙）+ 手稿 3 篇（甲/乙/丙）+ 节点池 5 张卡片 + 画布/手稿/节点池各一组文件夹。

| 步骤 | 断言 |
|---|---|
| 手稿列表排序 | 把「稿甲」拖到「稿丙」下方，顺序真的变成 乙→丙→甲 |
| 排序落库 | 刷新页面后仍是新顺序（不是只改了内存） |
| 手稿文件夹排序 | 把「手稿夹甲」拖到「手稿夹乙」下方，树里顺序真的变化；载荷是 `folder:甲` 这种带前缀的 |
| 手稿文件夹落库 | 刷新后仍是新顺序 |
| 画布列表排序 | 把「画布甲」拖到「画布丙」下方，左栏顺序真的变化 |
| 卡片拖入画布 | 「文字在上、图片在下」的卡片拖进画布后，正文里**文字和图片都在** |
| 节点池卡片排序 | 池内把「排序卡甲」拖到「排序卡乙」下方，卡片位置真的换 |
| 节点池卡片落库 | 刷新后仍是新顺序 |
| 节点池文件夹排序 | 把「排序夹甲」拖到「排序夹乙」下方，树里顺序真的变化 |
| 画布文件夹排序 | 把「画布夹甲」拖到「画布夹乙」下方，左栏顺序真的变化 |
| 画布文件夹落库 | 刷新后仍是新顺序 |

两条重点：
- 「卡片拖入画布」钉住的是"拖拽影子/落点只显示图片、丢掉文字"的回归。
- 四组"排序落库"钉住的是"界面看起来动了、库里没写"的回归——这轮节点池卡片就是这个毛病：服务端 `sortOrder` 写对了，渲染却没读它。

> 📌 面板/侧栏没真正滑入时，元素的 `getBoundingClientRect()` 会落在视口外，鼠标坐标全错、拖拽静默失败。脚本里等 `r.right <= window.innerWidth` 就是为了这个。

## legacy-upgrade.mjs 覆盖什么

验证「生产旧库能不能被新版本直接接管」。做法是拿一份**真实的老库副本**启动服务，
让 `runMigrations` 自己跑，然后从接口侧检查：

| 检查点 | 断言 |
|---|---|
| 旧数据可读 | 43 篇手稿、23 张卡片全部读得到 |
| 新列已补 | 每篇手稿都返回 `sortOrder`，老数据默认 0 |
| 排序可用 | `PUT /api/manuscripts/reorder` 返回 200，三篇相对顺序与写入一致 |
| 可写入 | 升级后能新建手稿（说明表不只是读得动） |

### 怎么复现

```bash
# 1. 复制一份真实老库（连同 -wal / -shm，否则会看到空表）
cp .e2e/e2e.db .e2e/legacy-real.db
cp .e2e/e2e.db-wal .e2e/legacy-real.db-wal
cp .e2e/e2e.db-shm .e2e/legacy-real.db-shm

# 2. 用这份库启动服务（迁移会自动执行）
NODE_ENV=production PORT=8123 WS_PORT=8123 \
  DB_FILE=.e2e/legacy-real.db JWT_SECRET=legacy-test-secret-0123456789abcdef \
  CSRF_SECRET=legacy-test-csrf-0123456789abcdef \
  ALLOWED_ORIGINS=http://127.0.0.1:8123 \
  node --import tsx backend/src/index.ts

# 3. 校验
npm run e2e:legacy
```

> ⚠️ **SQLite 的 `-wal` / `-shm` 必须一起复制**。只拷 `.db` 会看到空表——
> 数据还在 WAL 里没落盘。做真实备份时同理，这是最容易踩的坑。

## legacy-folder-sort.mjs 覆盖什么

同一个旧库、同一个服务，这次验的是"本轮新增的写库路径在老库上也能跑"。

本轮**没有新增任何列**（`manuscript_folders.sort_order`、`folders.sort_order` 早就存在），
但手稿文件夹与画布文件夹这两个 `PUT` 路由是本轮才开始真的接收 `sortOrder` 的——
之前前端把值发过来会被静默丢掉。老库里这两个字段全是 0，所以必须验：

| 检查点 | 断言 |
|---|---|
| 新建文件夹 | 旧库上能手稿夹、画布夹各建两个 |
| sortOrder 可写 | 两个 `PUT` 都返回 200，且列表按新顺序返回（乙 100 排在甲 200 前） |
| 非数字被拒 | `sortOrder: 'abc'` 返回 400，且原值仍是 200（不能写坏） |
| 老数据没被动 | 手稿数量不受影响 |

跑法跟上一条完全一样（同一个服务），只是换成：

```bash
npm run e2e:legacy:sort
```

## 前置条件

1. **服务在跑，并且托管了构建好的前端**
   ```bash
   npm run build:frontend
   # backend 启动时会托管 frontend/dist；示例：
   NODE_ENV=production PORT=8000 WS_PORT=8000 DB_FILE=./mindmap.db \
     CSRF_SECRET=xxx JWT_SECRET=xxx ALLOWED_ORIGINS=http://127.0.0.1:8000 \
     node --import tsx backend/src/index.ts
   ```

   ⚠️ **`NODE_ENV=production` 时必须给 `CSRF_SECRET`**：缺了它 `/api/csrf-token` 直接 500，
   登录/注册全部卡住，而页面看起来只是"点了没反应"。

2. **headless Edge 带 CDP 启动**
   ```bash
   msedge --headless=new --remote-debugging-port=9223 \
     --user-data-dir=<临时目录> about:blank
   ```

3. `full-flow.mjs` 每次运行都会注册一个新账号（`e2e+<时间戳>@mindmap.local`），
   所以不需要预先准备账号，也不会污染已有数据。

## 运行

```bash
node e2e/full-flow.mjs
E2E_BASE=http://127.0.0.1:8000 E2E_CDP=http://127.0.0.1:9223 node e2e/full-flow.mjs

npm run e2e:full       # 全量用户流程
npm run e2e:folders    # 删文件夹专项
npm run e2e:drag       # 拖拽排序 / 拖入文件夹 / 拖拽影子
npm run e2e:ui         # ui-smoke（需要预先存在的账号与画布）
```

截图与 `*-results.json` 落在 `e2e/.tmp/`（已 gitignore）。

## 几个别踩的坑

- **必须 `Emulation.setDeviceMetricsOverride`**：headless 默认视口 500×320，布局会塌陷，坐标点击全部错位。
- **导航后不能只等 `location.pathname`**：`Page.navigate` 会先提交 URL，此时 DOM 还是上一页，
  后续选择器全部落空。要等页面特有的元素（`goto(url, readyExpr)`）。
- **原生 `prompt`/`confirm` 必须先排应答再点按钮**：弹窗在点击时就同步阻塞，
  点完再 push 只能拿到空答复（新建文件夹会静默失败）。
- **画布内容在失焦时才提交**：粘贴完图片要点别处（用页头空白，别点画布，画布内点击会新建节点）。
